<threat_model>
## Trust Boundaries

| Boundary | Description |
|---|---|
| Browser -> dispatch endpoint | Client controls text, images, and extra fields; it cannot be trusted to declare intent. |
| Dispatch endpoint -> task IPC | Serialized actionable payloads are consumed by a local Node watcher with timestamp deduplication. |
| Webhook/event path -> browser | Broadcast data is persisted and rendered as UI-visible message/status content. |

## STRIDE Threat Register

| Threat ID | Category | Component | Severity | Disposition | Mitigation Plan |
|---|---|---|---|---|---|
| T-01-07 | Spoofing | client-supplied intent metadata | high | mitigate | Never accept `mode`, `intent`, or similar request fields as routing authority. |
| T-01-08 | Tampering | serialized queue payload | high | mitigate | Preserve server-generated model/timestamp fields and test exact watcher-required keys. |
| T-01-09 | Repudiation | queue writes and response mode | medium | accept | Existing application logging/history remains the audit record; new durable audit system is out of scope for CHAT-01. |
| T-01-10 | Information disclosure | response/message rendering | medium | mitigate | Use framework persistence/events and bounded, non-executable response text. |
| T-01-11 | Denial of service | oversized or expensive text/image classification input | medium | mitigate | Reject text over `TASK_TEXT_MAX_LENGTH = 10,000`, more than 5 images, any decoded image over 5 MiB, or aggregate decoded images over 20 MiB before storage/IPC; keep discernment deterministic/local. |
| T-01-12 | Elevation of privilege | false casual bypass | high | mitigate | Default uncertain, mixed, imperative, and attachment-bearing requests to actionable. |
</threat_model>
